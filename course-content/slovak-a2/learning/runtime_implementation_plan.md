# План внедрения курса Slovak A2 в приложение

## Цель

Добавить материалы A2 в существующий интерактивный курс, сохранив весь
прогресс A1 и текущие пользовательские сценарии. Источником содержания служат
проверенные PDF и `learning_roadmap.md`; PDF не подключаются как замена урокам,
а преобразуются в полноценные интерактивные темы.

Работа выполняется небольшими принимаемыми этапами. Сначала создаётся один
полный урок 2.1, после его ручной проверки уточняется общий шаблон, и только
затем добавляются остальные темы модуля 2.

## Неподвижные правила

- A1 продолжает работать без изменения существующих slug, activity ID и
  browser-storage keys.
- Прогресс A1 и A2 не смешивается.
- Все slug и activity ID A2 получают явный префикс `a2-`.
- Старые ключи итогов модулей `"1"`-`"8"` читаются как данные A1.
- Учебный материал живёт во frontend; SQLite хранит состояние.
- Frontend обращается к backend только через `frontend/app/lib/api.ts`.
- Каждый урок находится в отдельном файле.
- Ответы ученика проверяются существующим общим движком, без отдельной логики
  оценки внутри React-компонентов.
- UI/Playwright-тесты запускаются только по прямому запросу владельца.

## Этап 1. Каркас A2 и пилот 2.1

1. Создать отдельную TypeScript-дорожную карту A2 Module 2 с 12 темами.
2. Создать каталог `frontend/app/data/a2/modules/module2/`.
3. Добавить фабрику уроков с префиксом activity ID `a2-m2-`.
4. Перенести тему 2.1 «Nominatív множественного числа: предметы и понятия».
5. Добавить статическую проверку соответствия roadmap, файлов и ID.
6. Пока не подключать A2 к интерфейсу и сохранению прогресса.

Результат этапа: содержательно полный урок 2.1 существует и проверяется, но не
может случайно повлиять на действующий курс A1.

## Этап 2. Разделение состояния A1 и A2

1. Добавить уровень курса `A1 | A2`, по умолчанию `A1`.
2. Сохранить совместимое чтение текущего `activeModule` и `selectedSlug`.
3. Квалифицировать новые ключи итогов: например, `a1:2` и `a2:2`.
4. Добавить совместимую backend-схему состояния и backup без удаления данных.
5. Проверить восстановление старого состояния A1 и нового состояния A1/A2.

Результат этапа: переключение уровня не повреждает и не подменяет прогресс.

## Этап 3. Подключение A2 к интерфейсу

1. Добавить спокойный переключатель уровня A1/A2.
2. Для A2 временно показывать только готовый Module 2.
3. Перевести общие экраны с прямых импортов `a1CourseModules` и
   `allA1Lessons` на выбранный каталог курса.
4. Проверить темы, материал, закрепление, итог, словарь, чтение, упражнения,
   домашнюю работу, статистику и шпаргалки.

Результат этапа: урок 2.1 можно пройти целиком в приложении.

## Этап 4. Ручная приёмка пилота

Владелец проверяет урок 2.1 и отвечает на четыре вопроса:

1. Объяснение достаточно простое, но уже соответствует A2?
2. Удобны ли объём и порядок пяти учебных шагов?
3. Достаточно ли упражнений на формы, согласование и собственную фразу?
4. Корректно ли сохраняются слова, ошибки, итог и домашняя работа?

После замечаний обновляются фабрика и правила следующих уроков. До этой
приёмки массовое создание остальных 11 тем не начинается.

## Этап 5. Остальные темы Module 2

Темы добавляются небольшими сериями:

1. 2.2 — Nominatív множественного числа: люди.
2. 2.3-2.4 — Akuzatív единственного и множественного числа.
3. 2.5-2.7 — три темы Genitív.
4. 2.8-2.10 — Datív, Lokál и Inštrumentál.
5. 2.11-2.12 — пространственные триады, управление и обращение.

После каждой темы выполняются сверка с её PDF, проверка идентификаторов,
валидация содержания и ручная приёмка владельцем.

## Учебные разделы Module 2

1. **Множественное число и Akuzatív:** 2.1-2.4.
2. **Genitív:** 2.5-2.7.
3. **Datív, Lokál и Inštrumentál:** 2.8-2.10.
4. **Система падежей и движение:** 2.11-2.12.

## Минимальный контракт каждого урока

- точное соответствие номеру, названию и результату PDF;
- простое русское объяснение без повторного преподавания A1 с нуля;
- не менее пяти содержательных разделов;
- практика после каждого обязательного раздела;
- упражнения на распознавание, ввод формы, исправление ошибки и продукцию;
- словарь из слов и полезных фраз урока;
- знания, итоговая проверка и данные для повторения ошибок;
- словацкая клавиатура для текстовых ответов;
- уникальные slug и activity ID с префиксом A2.

## Проверки завершённого Module 2

- отдельная `validate:a2` и общая проверка уникальности идентификаторов;
- существующая `validate:a1` без регрессий;
- frontend unit-тесты и TypeScript;
- backend-тесты состояния курса и backup;
- production build;
- repository audit и `git diff --check`;
- ручная проверка интерфейса владельцем.

## Текущая точка продолжения

Выполнить этап 1: создать изолированный каркас A2 и один полный урок 2.1, не
меняя runtime, backend-схему и пользовательский прогресс.
