# Формат курса

Каноническая структура описана TypeScript-типами в
`frontend/app/data/courseTypes.ts`. Каталог Slovak A1 собирается в
`a1Course.ts`. Все Modules 1–8 находятся в `modules/moduleN/`: каждая из 83
тем хранится в собственном файле `lessons/<slug>.ts`, фабрики содержат только
общую логику построения урока, а `index.ts` задаёт порядок и проверяет полноту
набора. Общего файла содержания для нескольких тем нет.

Проверка пользовательских ответов, compatibility-чтение прежнего формата
парных ответов, выбор заданий закрепления и построение итоговых вопросов
находятся в `frontend/app/data/coursePractice.ts`. UI вызывает эту чистую
логику и не дублирует правила оценки в React-компонентах.

Module 2 сохраняет семь slug из roadmap и делится на три группы: род
существительных, число и словарная форма, называние и наличие. Каждый его урок
содержит не менее пяти секций и пяти пошаговых практик; activity ID используют
стабильный префикс `m2-`.

Module 3 сохраняет шесть slug из roadmap, делится на группы согласования,
указания/описания и выбора/связности и использует стабильный префикс `m3-`.
Материал шести уроков сверён с шестью PDF владельца: добавлены вопросы
`aký/aká/aké` и `akí/aké`, формы `váš` и `jeho/jej/ich`, 11 цветов, модели
`nie A, ale B`, `aj A, aj B` и последовательность
`najprv — potom — nakoniec`. Материал ограничен именительным падежом;
падежные формы из диалогов источника остаются для Module 4, кроме явно
помеченных готовых бытовых вопросов.

Module 4 сохраняет 11 slug и использует стабильный префикс `m4-`. Подробные
парадигмы не являются целью: падежи вводятся через вопросы, предлоги и
частотные бытовые модели A1. Материал сверён с 11 PDF владельца: различаются
субъект и объект, формы полного согласования в Akuzatív, `v/vo` и `na` с
Lokál, Genitív количества/отсутствия/направления, карта управления пяти
падежей, триады `Kde? — Kam? — Odkiaľ?`, частотные модели Datív и
Inštrumentál и команды простого маршрута.

Module 5 собирается из `modules/module5/`, сохраняет 11 slug и
использует префикс `m5-`. Его граница — настоящее время, частотные
неправильные/возвратные глаголы, модальность, просьбы и базовый императив.

Module 6 собирается из `modules/module6/`: 18 сценариев используют
префикс `m6-` и интегрируют ранее изученную грамматику в бытовые задачи A1.

Module 7 сохраняет семь slug и activity ID, но показывает их в четырёх
учебных разделах: прошедшее время, будущее и планы, вчера — сегодня — завтра,
приглашение и договорённость. Такое объединение не меняет сохранённый прогресс
отдельных тем и словарные точки разблокировки.

Module 8 сохраняет девять slug и activity ID, но показывает их в четырёх
учебных разделах: общение и взаимопонимание, сообщения и самопрезентация,
практическое взаимодействие и итоговые сценарии A1. Темы распределены по
схеме `3 + 3 + 2 + 1` без изменения сохранённого прогресса.

Обязательные инварианты:

- уникальные и стабильные module/lesson/activity ID и slug;
- явный порядок модулей, уроков и секций;
- корректные `sectionIndex` для практик;
- ссылки progress, vocabulary, topic groups и CEFR только на существующие slug;
- изменение идентификатора требует compatibility/migration пути для
  сохранённого состояния.
- В исходных данных `pairs` варианты можно держать в одинаковом смысловом
  порядке для удобства редакторской проверки. На экране тематического и
  итогового теста `coursePractice.ts` стабильно распределяет правильные ответы
  по разным позициям: порядок не прыгает при перерисовке, а строки и одинаковые
  по ширине столбцы сохраняются. Проверка должна подтверждать и наличие ответа
  среди вариантов, и разнообразие его экранных позиций.

Каталог A2 находится в `data/a2/` и загружается отдельно при выборе уровня.
Module 1 содержит все семь тем 1.1–1.7 и три группы (1.1–1.2 / 1.3–1.5 /
1.6–1.7), отдельную фабрику `a2-m1-` ID и итог на 14 вопросов.
Диагностика — самооценка без сброса A1; произношение — самостоятельное чтение
и знание правил, не автоматическая оценка речи. Добавление Module 1 перед
Module 2 сохраняет старую позицию по slug и завершение `a2:2`.
В Module 2 готовы все темы 2.1–2.12: четыре группы — множественное число /
Akuzatív, Genitív, Datív / Lokál / Inštrumentál, система падежей и движение.
Каждая тема — отдельный файл
с фабрикой `a2-m2-` ID;
не менее пяти секций/практик, трёх проверок знаний и двух итоговых вопросов.
Новые темы одновременно регистрируются в index и лёгком coursePositionCatalog.
`validate:a2` сверяет roadmap, оба каталога, ID, ответы уроков/закрепления и
восстановление позиций; прежний итог меньшего пакета не закрывает расширенный.
Полный набор содержит 24 итоговых вопроса; проверяется совместимость прежних
наборов из 1, 4, 7 и 10 тем. Проверка не должна принимать неверные варианты
choice/pairs из-за нормализации текста. Правило запятых в обращениях 2.12
проверяется словесным choice: текстовый движок намеренно игнорирует пунктуацию.

Module 3 содержит все девять тем 3.1–3.9: три группы (3.1–3.4 / 3.5–3.7 /
3.8–3.9), фабрику `a2-m3-` ID и итог на 18 вопросов. Каждый урок содержит
не менее пяти основных секций, семь практик всех четырёх типов и практику
каждой секции. Свободное письмо проверяется в чате; автоматические задания
задают конкретные слова/модели и принимают явно перечисленные варианты.
Добавление Module 3 сохраняет позиции, ответы и итоги Modules 1–2/A1.
Названия модулей английские; темы и объяснения русские. A1/A2 используют
одну шапку: выбор модуля, уровень, название, описание и прогресс.

Module 4 начат темами 4.1–4.3 по трём PDF: рассказ и видовые пары,
один раздел, фабрика `a2-m4-`, итог на шесть вопросов. Темы 4.4–4.12
ещё не подключены; в каталоге нет пустых будущих уроков. При добавлении
следующей серии сохраняются номера существующих практик/вопросов, а старый
отправленный итог переоткрывается без удаления ответов и без изменения A1.

Проверка A1: `npm.cmd run validate:a1`; A2: `npm.cmd run validate:a2`.
YAML больше не является источником
runtime-курса.
